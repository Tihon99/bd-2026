# Проверка Meta Kaggle на реальных данных

Дата выгрузки: 2026-11-06. Источник: Kaggle `kaggle/meta-kaggle`.

## Данные

В `data/raw/` скачаны только таблицы, используемые проектом: Competitions, Users, Teams, TeamMemberships, Tags, CompetitionTags, Kernels, KernelTags и Submissions. Размер папки около 6,5 ГБ. CSV игнорируются Git-ом.

Проверены заголовки всех CSV. Колонки, запрашиваемые загрузчиком, присутствуют. В актуальном CSV Teams поле `ScoreFirstSubmittedDate` заполнено нулями строк (9,658,324 команды), поэтому исходный расчёт опыта давал только пропуски.

## Исправления для изолированной проверки

В `src/features.py` хронология опыта считается по `TeamMemberships.RequestDate`, доступной в выгрузке. Повторные записи одного пользователя в рамках одного соревнования не увеличивают число прошлых соревнований.

В `notebooks/06_retention_by_tier.ipynb` заменена пустая дата первого сабмита на `RequestDate`, а список уровней строится по тем категориям, которые реально есть в таблице.

`PerformanceTier` исключён из признаков модели: выгрузка содержит текущий уровень участника, который может быть следствием успеха в исследуемом соревновании.

Пересборка `python -m src.build_dataset` завершилась: 458,878 команд, доля `top10` — 0.100. Parquet сохранён в `data/processed/teams_dataset.parquet`.

В актуальном модельном наборе: 458,878 строк и 7 колонок; пропуски есть только в двух признаках опыта (2,361 строка), у команд без известной истории членства. `PerformanceTier` сохранён в дополнительных признаках анализа, но не подаётся в модель.

## Выполнение ноутбуков

Все 10 ноутбуков исполнены на реальных таблицах; сводка — `reports/real-data-run/summary.txt`, текстовый лог — `reports/real-data-run/execution.log`. Графики сохранены в `reports/figures/`.

Модельное сравнение на разбиении по соревнованиям: 363,388 обучающих и 95,490 тестовых команд; тест охватывает 61 соревнование. ROC-AUC / PR-AUC: константа 0.500 / 0.100; правило по опыту 0.604 / 0.135; логистическая регрессия 0.644 / 0.215; LightGBM 0.662 / 0.237. Это результат конкретной текущей выгрузки и выбранного случайного разбиения, без подбора параметров.

## Повторная проверка устойчивости модели

После первоначального прогона модель повторно оценена на пяти разбиениях по CompetitionId. В каждом тесте 61 соревнование; LightGBM показал ROC-AUC от 0.649 до 0.665 и средний PR-AUC 0.233. Подробные оценки по каждой модели и seed приведены в `reports/model_stability_by_split.csv`, методика — в `docs/MODEL_STABILITY.md`. Это несколько случайных групповых разбиений одной выгрузки, а не временная валидация.
